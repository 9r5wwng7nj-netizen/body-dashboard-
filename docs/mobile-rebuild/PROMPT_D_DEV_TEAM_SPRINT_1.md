## Implement in dependency order

1. **Baseline and web persistence gate.** Inspect the actual working tree and run the appropriate existing checks. Write `outputs/D_WEB_PERSISTENCE_CONTRACT.md` before persistence edits: existing shapes/namespaces; proposed optional metadata keys/payload versions; coordinated Store writes; expected revisions/digests; transaction/receipt boundaries; startup reconciliation; fallback limits; backup/restore extension and cross-tab handling. Prove the contract with real IndexedDB failure/reload tests before expanding UI. Do not treat IndexedDB read errors as an empty install.
2. **Recoverable logging and lifecycle.** Implement durable draft/intent checkpoints and idempotent Start/Complete/Undo/Amend/Finish behavior through one coordinated writer. Acknowledgment follows transaction completion. Commit workout history, active-state clearing and recovery metadata consistently; preserve workout IDs and prevent late debounced snapshots from clobbering committed commands. Failed input stays recoverable with Retry; after restart check the receipt before replay. If storage cannot persist even the intent, accurately show the latest text as unacknowledged and keep export/preservation available.
3. **Fast, accessible workout rows.** Retain current navigation/Today/quick actions and make Resume direct. Show dated previous values and distinct suggestion/draft/pending/committed/failed states. One action accepts a valid ghost; new observations never count until explicit acceptance plus successful commit. Fix any finish path that auto-completes populated new rows, without changing the interpretation of existing historical records. Support direct load/reps editing, decimal/integer `inputmode`, select/replace, stable caret/focus, one-handed adjustment and undo. Keep RPE/joint detail optional and never copy prior feedback as current facts. Preserve supersets, set types and recoverability of all seven historical tracking types.
4. **Non-blocking timer and restoration.** Persist deadline/source consistently with completion, restore elapsed state after Safari/Home Screen suspension/relaunch, prevent duplicate timer intents and cancel only the completion's owned timer on undo. Collapse/expand/adjust/skip cannot cover inputs, completion or safe areas. Support a truthful foreground fallback; denied/unavailable notifications and background throttling must not block logging or imply a guaranteed background alarm.
5. **Existing workout-history import.** Add a local file picker/preview for unversioned Body fitness JSON and training-only extraction from full Body/Life v1/v2 backups. Reuse existing validators/import patterns safely; fitness export existence alone is not import support. Show source IDs/counts, units/timezone assumptions, known duplicates, changed source/local conflicts and quarantine. Default is no overwrite. Preserve original workout IDs, nested order/repeated exercises/supersets, values/precision, notes/RPE/types and raw unknown training fields. Retain ambiguous records for review instead of inventing data. Same title/date is not identity. Do not import unrelated Life records or call whole-app Replace from this flow.
6. **Atomic import/retry and portability.** Stage validated data/choices privately if necessary, then commit canonical changes + ledger/receipt in one final IndexedDB transaction. Keep the committed in-memory view until acknowledgment. Revalidate persisted target revisions after another tab edits them. Retry/restart checks the same job/receipt and imports an identical file without duplicates. Reconcile source = added + updated + skipped + quarantined, distinguishing added sets from sets in updated workouts. Preserve existing full backup restoration/photos as a separate flow and round-trip any optional new metadata without changing old records/envelopes unnecessarily.
7. **Hosted offline shell and safe updates.** Verify relative paths under the actual GitHub project prefix, manifest/start URL and service-worker scope. First prepare online; mark Ready offline only after the shell is available. Then test reopen/log/edit/finish offline without remote runtime assets. Review the current unconditional worker activation/client claim; do not reload over active/pending work, mix incompatible shell assets or lose the prior shell on failed update. Clear only obsolete Body cache generations. Never clear origin-wide caches/storage, inspect personal browser data or touch Life storage. A same-origin preview path is not a data sandbox.
8. **Analytics and regression coverage.** Retain completed-week consistency and seven-day weight average. Extract/test E1RM/delta rules and prepare/test optional EWMA where needed, using the synthetic vectors with explicit method/baseline/basis/gap labels. Do not silently replace the current weight trend or expand this slice into full analytics. Keep diet, recipes, photos, units, preferences and backup compatibility working. New diet completeness/snapshot features, broader analytics and coaching remain later MVP work unless needed to prevent a regression.
